# Realtor Lead Magnet Builder

Create a resource valuable enough to earn contact information without withholding the useful answer. Deliver a finished document and the minimum activation package needed to deploy it.

## Select mode and brand

Modes:

1. **Create**
2. **Audit**
3. **Update**
4. **Activate** an existing lead magnet

Confirm the audience before loading brand context:

- consumer buyer, seller, homeowner, relocator or investor;
- real estate agent or recruiting audience.

Use the consumer real estate brand for consumer guides. Route Realtor education, coaching, community or recruiting content to the relevant coach/content capability unless the user explicitly wants this skill.

## Resolve language

Use the language explicitly requested. If absent, ask before drafting:

1. Español
2. English
3. Bilingüe, as two complete editions

Do not mix languages inside one guide unless the user specifically requests a side-by-side format.

## Load context and inputs

Use relevant conversation, personal context and clearly named user-provided project resources. Do not depend on a specific file name and do not scan unrelated files.

Resolve:

- guide type and geographic scope;
- target segment and decision stage;
- desired CTA;
- agent name, brokerage, credentials and contact details;
- voice, colors and typography;
- verified local knowledge and supplied sources;
- desired deadline and output format.

Ask one grouped intake only for critical missing decisions. Use visible placeholders for reversible missing contact or design fields. Never use placeholders for material claims presented as facts.

## Choose research mode

Choose and state one:

- **Provided-facts mode:** use only user-supplied facts and sources.
- **Verified-local mode:** research current local facts and cite them.
- **Hybrid mode:** combine supplied expertise with verified public facts.

Default to Hybrid for a new local guide when browsing is available. Read [references/research-and-sources.md](references/research-and-sources.md).

Build a claim ledger: verified, user-provided, assumption, pending or prohibited. Date prices, incentives, inventory, rates, taxes, programs and market statistics.

## Design the guide

Read [references/guide-blueprints.md](references/guide-blueprints.md) and select the matching blueprint.

Before long drafting, provide an outline only when:

- the user requests collaboration;
- the guide is strategically ambiguous;
- research reveals two materially different directions.

Otherwise generate directly. Do not impose a confirmation step on a well-specified request.

Create:

- three title options;
- one primary title recommendation;
- cover promise;
- seven to ten useful sections appropriate to the guide;
- source notes or endnotes;
- agent/about page;
- one CTA page;
- disclaimer and verification notes where applicable.

Favor practical answers, checklists, decision tables, timelines, maps or comparisons. Every section should contain a local anchor or clearly explain why the information is universal.

## Protect factual integrity and Fair Housing

Read [references/quality-and-compliance.md](references/quality-and-compliance.md).

- Never invent market data, availability, incentives, schools, commute times, taxes, HOA/CDD, programs, zoning, safety, appreciation or results.
- Describe properties, processes, amenities and lifestyles without steering or protected-class targeting.
- For schools, use only verified names, boundaries or official resources; do not rate, rank or imply demographic fit.
- Separate general education from legal, tax, lending, insurance, inspection and appraisal advice.
- Attribute testimonials, production claims and credentials and use them only with authority.
- Provide a safe alternative when requested language is unsupported or noncompliant.

## Create the deliverables

Read [references/document-and-activation.md](references/document-and-activation.md).

Always deliver:

1. **Finished DOCX** using the document-creation capability.
2. **Design brief** compatible with any design workflow.
3. **Activation pack** containing:
   - filename and cover text;
   - landing-page headline and subheadline;
   - form title, description and CTA;
   - thank-you/delivery message;
   - delivery email;
   - delivery SMS only when consent and channel are in scope;
   - one organic promotion caption;
   - recommended next conversion event;
   - primary KPI.
4. **Source and pending-fact register.**

If the user requests a polished PDF, use the PDF capability after the content is approved and verify the rendered output. Do not refer the user to Claude or an undefined delivery script.

## Output order

1. Strategic angle and audience
2. Assumptions and verification status
3. Link to the DOCX
4. Design brief
5. Activation pack
6. Sources and pending items
7. Quality score

Do not paste the entire guide into chat when a downloadable document has been created unless the user asks.

## Quality gate

Score the result using [references/quality-and-compliance.md](references/quality-and-compliance.md). Do not deliver below 90/100. Correct every critical failure regardless of score.
