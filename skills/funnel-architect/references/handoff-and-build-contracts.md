# Handoff and Build Contracts

## Capability resolution

Resolve the exact installed capability before assigning work. Prefer:

1. domain-specific skill;
2. platform-specific skill;
3. general artifact skill;
4. direct completion by the current agent;
5. execution-ready brief when implementation access is unavailable.

Never block merely because a preferred skill name is absent.

## Shared brief

```yaml
funnel_goal:
audience:

```

## Typical build order

1. Research and verified fact base
2. Audience, offer and decision path
3. Lead magnet, event or conversion asset
4. Landing/capture experience
5. Thank-you/delivery experience
6. CRM schema, routing and consent
7. Nurture and human handoff
8. Traffic assets
9. Tracking and QA
10. Controlled launch

Change the order when a critical dependency demands it.

## Validation

Before accepting an asset, verify:

- message and offer match the shared brief;
- facts and claims are traceable;
- language and brand are correct;
- CTA and next state are unambiguous;
- consent and privacy are addressed;
- tracking event exists;
- downstream dependency can consume the output.

When an asset fails, return a precise correction request instead of silently changing the funnel thesis.
